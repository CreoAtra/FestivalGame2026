# フルーツキャッチゲーム 要件定義書

最終更新: 2026-10-01

---

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| タイトル(仮) | フルーツキャッチゲーム |
| 概要 | 上から降ってくるフルーツをキャラクターでキャッチし、制限時間内にスコアを稼ぐスマホ向けブラウザゲーム |
| 開発体制 | 8人チーム |
| 作業時間 | 1人あたり約8時間(目安) |
| 対象環境 | Chrome(iOS / Android) |
| 公開先 | GitHub Pages |

---

## 2. 技術方針

| 項目 | 内容 |
|---|---|
| 描画・ゲームループ | p5.js(`setup()` / `draw()`) |
| UI操作 | jQuery(スコア表示の更新、ボタンのイベント処理、画面切り替え) |
| ライブラリ読み込み | CDN の `<script>` タグ。`package.json` は使用ライブラリの管理用として併記 |
| ライブラリ追加時 | `package.json` に追記し、`index.html` に `<script>` タグも追加する |
| 当たり判定 | 矩形判定(AABB) |
| 座標系 | 画面左上を原点(0, 0)、単位は px |
| Canvasサイズ | 400 × 700(内部解像度は固定し、CSSで画面幅に合わせて拡大縮小) |
| 操作ボタン | Canvas外のHTML要素として配置 |
| スコア保存 | `localStorage` |
| バージョン管理 | GitHub。個人ブランチを切ってからマージ |

## 3. ゲーム仕様

### 3.1 基本ルール

| 項目 | 内容 |
|---|---|
| 制限時間 | 60秒 |
| 時間の上限 | 90秒(時計アイテムで延長しても90秒を超えない) |
| ゲームの終了条件 | 時間切れ、またはライフが0になる |
| 終了したときの扱い | どちらの終わり方でも失敗ではなく、そこまでのスコアで終了。スコアは無効にならず、ランキングにもそのまま登録される |
| ライフ初期値 | 3(仮) |
| ライフ減少条件 | ダメージフルーツをキャッチした場合のみ(取り逃しでは減らない) |

### 3.2 落下オブジェクト(全6種)

| 種類 | 効果 | 出現率 | 備考 |
|---|---|---|---|
| 通常フルーツ A | スコア加算 | 高 | 3種とも同じ得点 |
| 通常フルーツ B | スコア加算 | 高 | 3種とも同じ得点 |
| 通常フルーツ C | スコア加算 | 高 | 3種とも同じ得点 |
| 高得点フルーツ | 高いスコア加算 | レア | 得点は担当の方が決めてください |
| ダメージフルーツ | ライフ -1 | 中 | スコアは減らさない |
| 時計 | 残り時間を延長 | レア | 上限90秒。延長量は担当の方が決めてください |

- 落下速度は通常時は全種共通です
- 具体的な得点・出現率・出現間隔・延長量は、担当の方が遊びやすいと思う値を決めてください(あとから全員で調整するので、まずは仮の値で大丈夫です)

### 3.3 速度上昇(発展機能)

- 残り時間が **10秒**を切ったら発動(仮の値です。実際に遊んでみて変えてもらって構いません)
- プレイヤーの移動速度を上昇させる
- 落下速度も上げるかどうかは、担当の方が決めてください

### 3.4 バランスの考え方

**「落下にかかる時間 > キャラが画面端から端へ移動する時間」になっていると、どこに落ちてきても取りに行けるゲームになります。**

- 落下距離は約640px(画面上端から地面まで)
- p5.js の `draw()` は毎秒約60フレーム

| 落下速度 | 640px落ちるまで |
|---|---|
| 2px/フレーム | 約5.3秒 |
| **3px/フレーム(初期値の目安)** | **約3.6秒** |
| 4px/フレーム | 約2.7秒 |
| 6px/フレーム | 約1.8秒 |

- 初期値の目安:**落下 3px/フレーム、キャラ移動 4〜5px/フレーム**
- 落下時間が移動時間を下回ると「見えているのに間に合わない」状態になってしまうので、落下速度(フルーツ担当)とキャラ移動速度(キャラクター担当)は、お互いの値を見ながら調整してもらえると助かります

## 4. 操作仕様

| 項目 | 内容 |
|---|---|
| 操作方法 | 画面下部のボタン(左移動・右移動・ジャンプ)によるタッチ操作のみ |
| ボタン形式 | 画面下部に常に固定表示されるボタン。スクロールやスワイプでは動かず、指で直接タップして操作する。Canvas外のHTML要素として配置 |
| ボタン配置 | 画面下側で押しやすい位置(具体的な配置はUI担当の方が決めてください) |
| 左右移動 | ボタンを押している間ずっと移動し続ける |
| ジャンプ | ジャンプ中も左右移動が可能 |
| 同時押し | 許可します(移動しながらジャンプできます)。左右を同時に押したときは「止まる」か「後に押した方を優先」のどちらかに決めてください |

## 5. 画面仕様

### 5.1 画面遷移フロー

```
タイトル画面 → ゲーム画面 → 結果画面 → リトライ(ゲーム画面へ) / タイトルに戻る
```

### 5.2 各画面の表示内容

**タイトル画面**
- ゲームタイトル
- スタートボタン
- ハイスコア表示
- 操作説明(任意)

**ゲーム画面**
- スコア
- 残り時間
- ライフ
- ベストスコア(実装する場合)
- 操作ボタン(左・右・ジャンプ)

**結果画面**
- 今回のスコア
- 自己ベスト更新時の演出
- ランキング(ローカル保存の上位5件)
- リトライボタン / タイトルに戻るボタン

## 6. キャラクター・アセット仕様

| 項目 | 内容 |
|---|---|
| キャラクターサイズ | 幅50px × 高さ60px |
| キャラクターの当たり判定 | 見た目より少し小さめ(幅40px程度)にすると、理不尽な当たり判定になりにくいです |
| キャラクターの移動速度 | 担当の方が決めてください(目安 4〜5px/フレーム) |
| キャラクターの位置 | 地面に立っている。地面の線のY座標 = **640**(足元がここに乗るので `player.y` は 580) |
| フルーツ画像サイズ | 表示 40×40px。画像ファイルは実寸の2倍(80×80px)で用意し縮小表示 |
| 画像形式 | png |
| 画像の入手 | フリー素材・自作のどちらでも構いません |

### 6.1 画像ファイル名

画像は `assets/` フォルダに、以下の名前で置いてください。

| 対象 | ファイル名 | `type` の文字列 |
|---|---|---|
| キャラクター | `assets/player.png` | — |
| 通常フルーツ A(りんご) | `assets/apple.png` | `"apple"` |
| 通常フルーツ B(バナナ) | `assets/banana.png` | `"banana"` |
| 通常フルーツ C(ぶどう) | `assets/grape.png` | `"grape"` |
| 高得点フルーツ | `assets/bonus.png` | `"bonus"` |
| ダメージフルーツ | `assets/damage.png` | `"damage"` |
| 時計 | `assets/clock.png` | `"clock"` |

- フルーツは `type` の文字列とファイル名を合わせているので、`assets/` + `type` + `.png` で画像のパスが作れます
- 画像がまだ用意できていない間も、この名前で読み込むコードを先に書いて進めてもらって大丈夫です。あとから同じ名前のファイルを置けばそのまま表示されます
- 通常フルーツの中身(りんご・バナナ・ぶどう)は仮のものなので、別の果物にしたい場合は Discord で共有してください

## 7. 役割分担(8人体制)

| # | 担当 | 主な作業 |
|---|---|---|
| 1 | キャラクター操作 | 左右移動・ジャンプの実装、重力処理、キャラ座標の管理、画面端での移動制限 |
| 2 | フルーツ生成 | 6種類の出現ロジック、出現位置のランダム化、落下速度・出現頻度の管理、画面外に落ちたフルーツの削除 |
| 3 | 当たり判定 | キャラとフルーツの矩形判定、ジャンプ中のY座標を含めた判定、判定結果をゲームロジック担当へ渡す |
| 4 | ゲームロジック(結合役) | 制限時間の管理、スコア加算、時計アイテムの時間延長、終了判定、ゲームループ全体の管理、各担当のコードの結合 |
| 5 | UI | ゲーム中の表示(スコア・残り時間・ライフ)、操作ボタンの見た目と配置、画面サイズに応じたレイアウト調整 |
| 6 | アセット・演出 | キャラ/フルーツ6種の見た目、キャッチ時のエフェクト、BGM・効果音(余裕があれば) |
| 7 | 発展機能 | 残り時間が少なくなった際の速度上昇、ライフ制の実装 |
| 8 | タイトル・結果・ランキング | タイトル画面、結果画面、ローカルランキング(`localStorage`で上位5件を保存・表示)、画面遷移の管理 |

## 8. 担当間の連携ルール

### 8.1 基本の考え方

担当をまたいでデータを触ると、どこで値が変わったのか分からなくなってしまいます。そこで、次の2つを基本にしています。

- **自分が担当するデータだけを書き換えて、他の担当のデータは読むだけにする**
- **1つの値を書き換えるのは1人だけにする**(スコアを増やすのはゲームロジック担当だけ、キャラの座標を動かすのはキャラクター担当だけ、など)

例外が1つだけあります。**キャッチしたフルーツを `fruits` から取り除くのは、当たり判定担当が行います。** 取ったフルーツを配列に残したままだと、次のフレームでも重なったままになり、1個のフルーツで何度もスコアが入ってしまうためです。フルーツを新しく足したり落としたりするのはフルーツ生成担当のままで、取り逃して画面外に落ちたフルーツを消すのもフルーツ生成担当です。

### 8.2 データの流れ

```
[キャラクター担当] ──→ player.x, player.y, width, height
                              ↓
[フルーツ生成担当] ──→ fruits[](type, x, y, width, height)
                              ↓
                      [当たり判定担当]
                              ↓ キャッチしたフルーツの種類
                    [ゲームロジック担当]
                       ↓            ↓
            [UI担当(表示のみ)]  [演出担当(タイミング受信)]
```

### 8.3 共通変数(暫定)

**`x` と `y` は「左上の角」を指します。中心ではありません。**

```
左端 = x        右端 = x + width
上端 = y        下端 = y + height
```

p5.js の `rect()` と `image()` は、何も指定しなければ左上を基準に描きます。そのため `image(img, player.x, player.y, player.width, player.height)` のようにそのまま渡せます。

キャラクターが地面に立っている状態は `player.y = GROUND_Y - player.height` になります(足元の `player.y + player.height` が地面の線 640 に乗ります)。

```javascript
// キャラクター(キャラクター操作担当が管理)
let player = {
  x: 175,            // 左上の角のX座標。画面の中央に置いた状態
  y: GROUND_Y - 60,  // 左上の角のY座標。地面に立っている状態
  width: 50,
  height: 60,
  velocityY: 0       // ジャンプ用。上向きがマイナス
};

// フルーツ(フルーツ生成担当が管理。取り除くのは当たり判定担当も行います)
let fruits = [
  { type: "apple", x: 100, y: 0, width: 40, height: 40, speed: 3 }
];

// ゲーム全体の状態(ゲームロジック担当が管理)
let gameState = {
  score: 0,
  timeLeft: 60,
  life: 3,
  isFinished: false  // ゲームが終わったかどうか
};
```

- `type` の文字列は 6.1 の表の通りに揃えてください(`"apple"`, `"banana"`, `"grape"`, `"bonus"`, `"damage"`, `"clock"`)

### 8.4 名前の付け方のルール

ルールは3つあります。上から順に大事なものです。

#### ① 他の担当も使う変数・関数は、名前をこの書類の通りにする(必須)

8.3 の `player` / `fruits` / `gameState` と、下の表の関数は、担当をまたいで使うものです。名前や中身が食い違っていると繋がらなくなってしまうので、ここだけは合わせてもらえると助かります。

**他の担当から呼ばれる関数**

| 担当 | 関数 | 役割 |
|---|---|---|
| キャラクター操作 | `updatePlayer()` | 毎フレーム、キャラの位置を更新する |
| キャラクター操作 | `drawPlayer()` | 毎フレーム、キャラを描画する |
| フルーツ生成 | `updateFruits()` | 毎フレーム、フルーツの生成・落下・削除を行う |
| フルーツ生成 | `drawFruits()` | 毎フレーム、フルーツを描画する |
| 当たり判定 | `checkCollisions()` | キャッチしたフルーツを判定して返す |
| UI | `updateUI()` | スコア・残り時間・ライフの表示を更新する |
| アセット・演出 | `playEffect(種類)` | 指定された演出を再生する |
| 発展機能 | `updateExtra()` | 速度上昇・ライフ関連の処理を行う |
| タイトル・結果・ランキング | `showTitle()` / `showResult()` | 各画面を表示する |

これらは `main.js` の `draw()` から呼び出します。中身をどう書くかは自由です。

#### ② 名前の重複を避ける(必須)

今回は全員のJSファイルを1つのページで読み込むので、**関数の外に書いた変数は、全ファイルで共有される1つの空間に並びます。**

そのため、2人が別々のファイルで同じ名前を使うと問題が起きてしまいます。

```javascript
// character.js
let speed = 5;

// fruit.js
let speed = 3;  // ← character.js の speed が上書きされてしまう
```

この場合、後から読み込まれた方の値で上書きされ、キャラの移動速度がおかしくなります。**エラーメッセージは出ません。** 「なぜか動かない」という形で現れるので、原因を見つけるのに時間がかかりがちです。

これを防ぐために、次の点を意識してもらえると助かります。

**(a) 変数はできるだけ関数の中に書く**

関数の中に書いた変数は、その関数の中だけのものになるので、他のファイルと重複しません。

```javascript
function updatePlayer() {
  let speed = 5;  // この関数の中だけで使われる。他ファイルと重複しない
  player.x += speed;
}
```

**(b) 関数の外に書く必要がある場合は、担当ごとの語を先頭に付ける**

毎フレーム値を覚えておきたい場合など、どうしても関数の外に書きたいときは、名前の先頭に担当を表す語を付けてもらえると重複しなくなります。

| 担当 | 先頭に付ける語 | 例 |
|---|---|---|
| キャラクター操作 | `player` | `playerSpeed`, `playerJumpPower` |
| フルーツ生成 | `fruit` | `fruitSpawnInterval` |
| 当たり判定 | `collision` | `collisionMargin` |
| ゲームロジック | `game` | `gameStartTime` |
| UI | `ui` | `uiFontSize` |
| アセット・演出 | `asset` / `effect` | `assetImages`, `effectList` |
| 発展機能 | `extra` | `extraSpeedRate` |
| タイトル・結果・ランキング | `screen` | `screenCurrent` |

**(c) p5.js が使っている名前は避ける**

`width`, `height`, `mouseX`, `mouseY`, `key`, `draw`, `setup` などは p5.js が元から使っている名前です。同じ名前を自分で作ると p5.js の動作が壊れてしまうので、避けてください。

#### ③ 書き方を揃える(できれば)

動作には影響しませんが、全員の書き方が揃っていると読みやすくなります。

| 対象 | 書き方 | 例 |
|---|---|---|
| 変数・関数 | 最初を小文字にし、単語の区切りを大文字にする | `playerSpeed`, `updatePlayer()` |
| 変更しない値 | すべて大文字、単語の区切りは `_` | `GROUND_Y`, `CANVAS_WIDTH` |
| true / false が入る変数 | `is` または `has` で始める | `isFinished`, `isPressingLeft` |

### 8.5 名前を変えた・増やしたときの共有方法

**自分のファイルの中だけで使っている名前は、報告なしで自由に変えてもらって大丈夫です。**

他の担当に関係する名前(8.3 の共通変数、8.4 ①の関数)を変えたり増やしたりするときは、次の2つをお願いします。

**1. 変える前に、ゲームロジック担当(結合役)に一声かける**

これらの名前は `main.js` から呼び出しているので、知らないうちに変わっていると結合のときに動かなくなってしまいます。先に相談してもらえると助かります。

**2. 変えた後に、Discord で共有する**

「何を」「どう変えたか」「誰に影響があるか」の3点が分かれば十分です。この要件定義書はリーダーが後でまとめて直すので、書類の編集は不要です。

例:

> `checkCollision()` を `checkCollisions()` に変えました(複数のフルーツを同時にキャッチできるようにしたためです)。main.js から呼んでいるので、結合時に影響があります。

### 8.6 担当者間ですり合わせておきたい項目

| 項目 | 関係する担当 |
|---|---|
| 落下速度とキャラ移動速度のバランス | 1 と 2 |
| 速度上昇の発動タイミング・上昇率 | 2, 4, 7 |
| ライフの減少条件と終了処理の統合 | 3, 4, 7 |
| ダメージフルーツの判定追加 | 2, 3, 7 |
| 画面の配色・フォントなどのデザインテイスト | 5, 6, 8 |
| 画面切り替えの管理方法 | 5 と 8(8番が画面遷移全体を管理する想定) |

## 9. ファイル構成

```
index.html      骨格。p5.js・jQuery・各JSファイルを読み込む
package.json    使用ライブラリの管理
style.css       UI担当が管理
character.js    キャラクター操作担当
fruit.js        フルーツ生成担当
collision.js    当たり判定担当
main.js         ゲームロジック担当(setup / draw、結合役)
ui.js           UI担当
assets.js       アセット・演出担当
extra.js        発展機能担当(速度上昇・ライフ制)
screens.js      タイトル・結果・ランキング担当
assets/         画像ファイル置き場(ファイル名は 6.1 を参照)
```

- これは出発点としての構成です。実装を進める中でファイルが大きくなってきたり、分けた方が書きやすいと感じたりしたら、担当範囲の中で自由にファイルを追加・分割してください
- ファイルを追加したときは `index.html` の読み込みタグも足して、追加したことを Discord で共有してもらえると助かります
